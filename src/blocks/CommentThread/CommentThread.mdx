# Comment thread

Comments with who wrote them and when, a reply box with a character count, and Edit and Delete for your own comments, with Undo. It's built from Avatar, RelativeTime, Field, Textarea, Button and Toast.

<Canvas of={Stories.Default} />

## When to use it

- Discussion attached to one thing, such as a task, a document or an order, where people reply and fix their own comments.
- Not for live conversation: use Chat, which stays at the newest message.
- Not for a log of what happened: use the Activity feed block.

## What each part is for

- **A region named by its heading** (1.3.1), so screen reader users can jump to "Comments". Pick `headingLevel` to fit the page.
- **Each comment is an article named by who and when**, "Ana Putri 2 hours ago", in an ordered list. Edit and Delete inside a comment are heard in that context, so they don't need longer names. The avatar is decoration, so the name isn't said twice.
- **The reply box has a visible label, the limit in its hint, and a count** (3.3.2). The count is read out when a few characters are left, not on every key. The box stops at the limit, counting characters the way people see them.
- **An empty reply says what to do**, in words next to the box, and focus goes back to the box (3.3.1). Posting clears the box and says "Reply posted" once. If `onReply` returns a promise, the button shows that it's working until it settles.
- **Ctrl+Enter (⌘+Enter on a Mac) sends** the reply or the edit, as in most comment boxes; Enter alone starts a new line, so nobody posts by accident.
- **Edit keeps focus where you are** (2.4.3). Focus moves into the comment's own box. Save, Cancel or Escape brings it back to Edit. Saving says "Comment saved".
- **Delete has Undo instead of a confirmation.** The comment leaves the list at once, and focus moves to the next comment (or the one before, or the heading), so it isn't lost. A toast offers Undo, which brings the comment back and focuses it. `onDelete` only runs once the toast has gone without Undo. The toast's time stops while it's hovered or focused, and F8 reaches it.
- **Loading says so once** (4.1.3). With `loading`, skeleton comments stand in for the list, which says it's busy; only the first is named ("Loading comments"), so a screen reader hears it once. The reply box is there from the start.
- **A load that fails says so** (3.3.1). Set `loadFailed` and pass `onRetry`: "Couldn’t load the comments" with Try again stands in for the list and the reply box, since a reply to comments no one can see would be a guess.
- **Another language**: every word is in `labels`, with English defaults. `replyHint` is a function of the limit.

## What stays your app's job

- Storing comments, and deciding who can edit or delete which (`mine`).
- Showing an error when posting or saving fails. The box keeps its text, so nothing is lost.
- Knowing when the comments failed to load: set `loadFailed`, and load them again in `onRetry`.
- Rendering a `Toaster` once in the app, for Delete's Undo.
