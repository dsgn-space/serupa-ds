# Product compare

Two to four products side by side, a row for each thing they could differ on, and a way to see only the differences.

<Canvas of={Stories.Default} />

## When to use it

- After someone chooses Compare on a few products in a shop.
- Not for plans with a price each month: that's the Pricing block.
- Not for one product's details: that's the Product page pattern.

## What each part is for

- **It's a table with a caption**: each product heads a column and each feature heads a row, so a screen reader says both for every cell. The first column stays put while the rest scroll on a phone (1.3.1, 1.4.10).
- **Yes and no are said in words**, not by a tick or a cross alone, and a missing value says "Not said" (1.4.1).
- **"Only what differs" says how many rows are shown** in a status line (4.1.3).
- **Each button's name ends with its product**, "Remove: Calm 300"; removing one moves focus to the next product's Remove, or the heading once none are left (2.5.3, 2.4.3).
- **Add to cart says what was added** in a toast (4.1.3).
- **While the products load**, set `loading`: one placeholder, named "Loading the products" (4.1.3). **A load that fails says so**: set `loadFailed` and pass `onRetry`, for its Try again.
- **A skip link** first, into main, as on every page.

<Canvas of={Stories.Empty} />

## What stays your app's job

- **What's compared.** Pass the features to show, in an order that puts what people choose on first, with a unit for numbers.
- **Keeping the list.** `onRemove` hears a product leaving; keep the list for the visit, so going back to the shop doesn't lose it.
- **Adding.** `onAddToCart` gets the product's id: reject when it can't be added.
