# List and detail

A list of things beside the one that's open, like messages in an inbox: two panes on a wide screen, one at a time on a phone.

<Canvas of={Stories.Default} />

## When to use it

- People move through many items one after another and come back to the list each time: messages, tickets, files.
- Not when each item is a page of its own that people share or bookmark: give each a URL and use the Detail page pattern.
- Not for a few items: a list of links is enough.

## What each part is for

- **Two regions named by their headings**, the list ("Messages (4)") and the open message, so a screen reader can jump between them (1.3.1).
- **The open item is marked** with a bar and `aria-current`, so its place is clear by sight and by ear.
- **The divider is a Splitter**: drag it, or focus it and use the arrow keys (2.1.1).
- **On a wide screen, focus stays in the list** when a message opens, so the arrow keys and Tab keep moving through the list.
- **On a phone, one pane at a time** (1.4.10). Choosing a message shows it alone with "Back to messages" first, and focus goes to its heading. Back shows the list with focus on the message it came from, still marked, so the place in the list is never lost (2.4.3).
- **Before anything is chosen on a phone**, the list shows alone. On a wide screen the first message opens, so the second pane is never empty.
- **A skip link** first, into main, as on every page.

## What stays your app's job

- **The messages.** Pass them as `messages`, newest first, and load more as the list scrolls with Load more if there are many.
- **The address.** Put the open message's id in the URL (`onSelect` hears it) so a reload or the browser's Back opens the same one.
- **Marking messages read**, and any actions on the open one (reply, archive): put them in a Toolbar above its heading.
