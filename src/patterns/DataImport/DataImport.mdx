# Data import

Bringing records in from a spreadsheet: choose a CSV file, match its columns to the app's fields, check every row before anything is saved, then see what was added, updated and skipped.

<Canvas of={Stories.CheckRows} />

## When to use it

- People already keep the records in a spreadsheet or another tool: customers, products, stock counts, contacts.
- More than a handful of records. For a few, a form that adds one at a time is quicker and catches mistakes as they're typed.
- Not for files the app reads without people checking them (a nightly feed): that needs a log and alerts, not a page.

## What each part is for

- **A Stepper with the step in words**, so people know how far they are and that there's a check before anything is saved. Each new step puts focus on its heading, so the change is said and Tab goes on from there (2.4.3, 4.1.3).
- **FileUpload in a Field**, taking only CSV, with the size limit in its hint and a line on how a spreadsheet saves one. Continue with no file, or a file with no rows under its headings, shows an ErrorSummary that takes focus and links to the file control (3.3.1, 3.3.3).
- **A Select for each field**, already matched where the file's heading names the field ("E-mail" for Email, "Town" for City), with "Not in the file" for optional fields. Matching a required field to nothing, or one column to two fields, is listed with what to do. Back keeps the file and the matches (3.3.7).
- **A preview of every row before saving.** A sentence counts what's ready in words (new and updated) and what has problems; the table lists the rows with problems first, each with a Badge that says "Problem", "Update" or "New" in words and the problem in its own column beside it, never only a color (1.3.1, 1.4.1). Each row keeps its line number in the file, so it can be found and fixed there.
- **Nothing saved until the last button**, which says how many records it saves ("Import 4 customers"). With rows that have problems, it asks for "Skip the rows with problems" first, so nobody loses rows without choosing to (3.3.4).
- **A failed import says so**, saves nothing, and the button becomes Try again, with the file and matches kept.
- **What happened, in a list:** added, updated and skipped, with the skipped rows still in the person's file to fix, then a way on and a way to import another file.

## What stays the app's job

- **The fields and their checks.** Replace `FIELDS` and `checkRows` with your record's fields and the rules your server applies, so the preview finds the problems the save would.
- **Matching existing records.** `existing` stands in for the app's own records: here a row whose email you already have updates that customer. Say in the check step how a match is made.
- **Saving.** `onImport` gets the rows to save; reject its promise when the save fails, and save all of them or none, so a retry doesn't add rows twice.
- **Large files.** This reads the file in the browser. For files of thousands of rows, read and check them on the server, show the first rows with problems and a count of the rest, and say how long saving will take.
- **Other formats.** For Excel files, read them with a library or ask people to save as CSV, as the first step's text does here.
