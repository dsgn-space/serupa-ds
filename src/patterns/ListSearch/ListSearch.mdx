# List with search and filters

A page of rows to search, filter, sort, select and page through, with the view kept in the address so Back, a reload and a shared link all show the same list.

<Canvas of={Stories.Default} />

## When to use it

- A list of things of one kind (projects, orders, people) long enough that people look for one, narrow it down, or act on several at once.
- Use a Table when the rows have columns worth comparing. For a list without columns (messages, notifications), keep the search and filters and use a List.
- Not for a search across the whole site: that's a results page, with the matches ranked rather than sorted.

## What each part is for

- **The Table toolbar block**: a search landmark ("Search and filter projects") with the search field and a labelled Select for each filter, then the results count in a status region. "8 of 24 projects" is read out as the search or a filter changes, without moving focus (4.1.3).
- **"Clear filters"** while anything is set. It empties the search and every filter, and puts focus on the search field, since the button that was pressed goes away (2.4.3).
- **Sort on the column headers.** Each sortable header is a button, and `aria-sort` says the order: press once for ascending, again for descending.
- **Selection** with a checkbox per row, named after it ("Select Mobile app"), and one in the header for the whole page. While any are selected, the action bar says "3 selected", holds the bulk actions and offers "Clear selection". The selection is kept across pages; a search or filter lets go of the selected rows it hides, so the count never includes rows nobody can see.
- **Archive and Export say what they did** in a toast. Archive takes the rows away at once, with Undo, and archives them for good (`onArchive`) only when the toast closes without Undo; Export calls `onExport` with the selected names.
- **No results** shown as an empty state that says what found nothing, in words ("No projects match “rocket”"), with "Clear filters" as the way out. Focus goes to the search field when it's pressed.
- **Pagination** with a summary ("11–20 of 24"). A change to the search or a filter goes back to page 1, so nobody lands on an empty page 3.
- **The address.** The search, filters, sort and page are written to the query string (`?q=app&status=Active&sort=updated&dir=descending&page=2`), with anything at its default left out, so the plain list has a plain address. `readView` and `writeView` show the mapping.
- **A skip link** first, into main, as on every page.

## What stays your app's job

- **Writing the address.** `onSearchChange` gets the new query string: write it with `history.replaceState` (or your router's equivalent), so typing doesn't add a history entry per letter. Pass the address's query string back as `search` when the page loads.
- **Searching on the server** for long lists: debounce the search, keep the count in step with what the server says, and show the table's loading state while it answers.
- **What the bulk actions do** (`onArchive`, `onExport`), and confirming the ones that can’t be undone.
- **Remembering the page size** and the columns someone chose, if the list offers them.
