# Password reset

Getting back into an account after forgetting its password: an email with a link, then a new password chosen from that link. It's where Sign in's "Forgot your password?" leads.

<Canvas of={Stories.Default} />

## When to use it

- An app where people sign in with an email and a password.
- Not for changing a password someone knows: that's the Account security pattern.
- Not for a code typed on the same page: Sign in's code step does that.

## What each part is for

- **One question per step.** First the email, then what to look for, then the new password, so each step is short and says what happens next (3.3.2).
- **The sent step says the same for every email**, "If an account uses ana@example.com, we sent it a link", so the page never tells a stranger who has an account.
- **Send it again** says in a status region that the link went, or that it couldn't, without moving focus (4.1.3). **Use a different email** goes back with the email kept (3.3.7).
- **Fields that say what they hold.** The email field has `autocomplete="email"`. The new-password step shows the account in a read-only field with `autocomplete="username"`, so a password manager knows which account to save the password for, and the password field has `autocomplete="new-password"`, so it can suggest a strong one (1.3.5, 3.3.8).
- **The rules are under the password from the start**, each saying in words whether it's met, not only by its mark (3.3.2).
- **A problem is said next to its field**, which gets focus, and a request or change that fails says so with what was typed kept (3.3.1, 3.3.3).
- **An expired link says why**, how long a link works and that it works once, with Send a new link back to the first step and the email kept.
- **Done says what changed**: other devices are signed out, then Sign in.
- **Each new step puts focus on its heading**, so a screen reader says the change and Tab goes on from there (2.4.3).

## What stays your app's job

- **Sending the link.** `onRequest` gets the email. Send the link only when an account uses it, but resolve either way, so the page says the same thing. Limit how often one email can ask.
- **Checking the link.** Open the page with `start="choose"` and the account's `email` when the link is good, and `start="expired"` when it's too old or used. Make each link work once, for the time `linkLife` says.
- **Storing the password.** `onReset` gets the new password. Check it on the server too, sign the account out everywhere else, and send an email saying the password changed.
- **Your own rules.** Keep the rules here the same as Sign-up's and Account security's, so a password one accepts isn't refused by another.
