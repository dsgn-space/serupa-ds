# Patterns

A pattern is a whole screen built from Serupa's components only: a page shell, a sign-in, a list with filters. Some of what WCAG 2.2 asks lives in the flow between components, not in any one of them: a sign-in that a password manager can fill (3.3.8), a form that keeps every answer when you go back (3.3.7), focus that lands on the right place after each step. A pattern shows one way to meet it, with tests that prove it.

Patterns are source for your app to own and change, not components to import.

## How to add one

1. Open the pattern's story and its guide. The guide says when to use it, what each part is for, and what stays your app's job.
2. Run `npx serupa-add Dashboard` (`npx serupa-add` alone lists them all). It writes `src/serupa/Dashboard.tsx`, with the blocks it builds on and its imports pointed at `@diki-stwn/serupa-ds`, from the release your app installed. By hand instead: copy `src/patterns/<Name>/<Name>.tsx` and change the imports from `../../components/<Component>/<Component>` to `@diki-stwn/serupa-ds`. Keep its first line, `"use client";`, where it has one: it uses state or handlers, so a Next.js App Router page needs it to build.
3. Replace the demo parts the guide names, such as the stand-in for your server's checks, with your own.
4. Keep the test: copy `<Name>.test.tsx` too, and run it against your copy, so a later change that breaks the flow is caught.

## What each one holds

Each folder in `src/patterns/` holds the stories, a test and a guide (`tools/test/contract.mjs` checks this). Their stories run the page rules in `tools/test/storybook.mjs` in every theme: one main landmark, everything inside a landmark, one h1 and no skipped heading level, no id twice, and a first Tab stop that is a skip link into main.

## Every state, not just the happy path

A copied screen meets every state it can be in, so each pattern has a story for each one, and the copy brings them all:

| State | Story | What the screen does |
| --- | --- | --- |
| Loading | `Loading` | Placeholders in the shape of what's coming, named once ("Loading activity"), and main is busy. |
| Load failed | `LoadFailed` | "Couldn't load …" in the content's place, with Try again (`onRetry`). |
| Empty | `Empty`, or a name of its own (`NoOrders`, `FirstRun`) | What will be here, and the one action that fills it. Never an empty table, a "0 items" count or filters for nothing. |
| Partly loaded | `Partial` | The parts that loaded show as usual; the part that didn't says so in its own place, with Try again. |
| Offline | `Offline` | "You're offline" first in main, then what still works and what needs a connection. The page keeps what it loaded. |
| Sending fails | `SendFails`, or a name of its own (`SaveFails`, `OrderFails`) | Everything entered stays, and it says what didn't go. |

A screen that loads data has the first five; a screen that sends something has the last two. Every pattern takes `online`: left out, it follows the browser, so a copied page says it's offline the moment the connection drops. `src/internal/patternStates.test.tsx` fails when a pattern is missing a state, and lists the states a screen can't be in with why (a quiz always has its questions).
