# RFC: 20.0.0

**Status:** Released in 20.0.0 (28 November 2026).

The color tokens get one naming rule, thing first, then variant, then state, and the values that go with it, so each state is one step from the one before it (Diki, 28 November 2026). Every breaking changeset until the release adds a section here.

## The color tokens name the thing first (`.changeset/color-tokens-thing-first.md`)

- **What breaks:** 63 color tokens are renamed (`--primary` is `--surface-brand`, `--primary-text` `--text-brand`, `--surface-muted` `--surface-sunken`, `--danger-text` `--text-danger`), five merge into another (`--surface-overlay` into `--surface-raised`, `--border-overlay` and `--border-elevated` into `--border-raised`, `--border-control` into `--border-strong`), and a few values move a step: `--surface-pressed` is zinc-200 and zinc-700 in dark, `--surface-inverse` is white in dark, `--field-readonly` is zinc-100 in light, `--field-raised` zinc-700 in dark. `--border-control-pressed` and `--textarea-resize-grip` go.
- **Why:** the names mixed three orders (`primary-text`, `text-muted`, `disabled-text`), so the token for a job had to be looked up rather than guessed. Thing first (surface, field, control, text, border), then the variant, then the state reads the same everywhere and sorts each family together. The values follow one ladder: in dark each state is one step lighter, and a border one step above its fill.
- **Migration:** `serupa-migrate` (`token-names-thing-first`) renames the CSS variables, `{color.<name>}` references and the utility classes in class lists. The old names keep working, deprecated, until 21.0.0.
