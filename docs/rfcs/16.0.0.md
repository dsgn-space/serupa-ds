# RFC: 16.0.0

**Status:** Open for comments

The second scheduled major: it makes the public surface say what things are for, and promises only that. A theme is a brand color and a mode; the easing tokens are roles named for what they move, with no scale of raw curves beside them; components read only roles for color, corners, shadows and motion; and of a component's classes, the block and its modifiers are public while its inner parts are its own. Every breaking changeset until the release adds a section here.

## A theme is a brand color and a mode (`.changeset/themes-are-colors.md`)

- **What breaks:** every theme differs from Blue only in its seven brand colors. The tactile look (Violet) and the modern look (Emerald) are removed, with `data-depth`, the 12 `depth-*` tokens, the 46 component `--…-depth…` tokens, `motion-toggle`, `ease-toggle`, `motion-draw` and `serupa-brand --look`. Emerald draws in the emerald ramp; the teal it drew in is the new `teal` brand. Every accent color of the palette is now a brand, light and dark.
- **Why:** two looks doubled the cost of every component change and every picture, for differences few apps asked for. A brand is its color, which is what people pick one for.
- **Migration:** `serupa-migrate` rewrites the removed motion roles and the `ease-toggle` class, and lists each place that uses a removed depth token, `data-depth` or the `emerald` brand. The changeset lists each removed name with what to use instead.

## The easing tokens are the roles (`.changeset/easing-roles.md`)

- **What breaks:** the 16 raw curves are removed, as tokens and as utility classes: `ease-in`, `ease-out`, `ease-in-out`, their `-cubic`, `-quart` and `-expo` forms, `ease-out-back`, `ease-spring-soft`, `ease-spring-snappy` and `ease-elastic`. What stays is `ease-enter`, `ease-exit`, `ease-move`, `ease-settle`, `ease-pop`, `ease-spring`, `ease-fling`, `ease-celebrate` and `ease-linear`. Each role keeps the curve it had, so no component moves differently.
- **Why:** 25 easing names for nine jobs made the choice for every new animation, and a curve picked by its shape (`ease-out-quart`) doesn't change when the role it stands in for does. A role says what moves, as the duration roles already do. Components only read roles already; apps get the same short list.
- **Migration:** `serupa-migrate` writes the role with the same curve for nine of the 16 (`ease-out-quart` is `ease-enter`, `ease-in-out` is `ease-move`, `ease-out-expo` is `ease-settle`, and so on). The other seven (`ease-in` and its strengths, `ease-in-out-quart`, `ease-in-out-expo`, `ease-spring-soft`) have no role with their curve: it writes the role that does their job and lists each place to check by hand. A bare `ease-in-out` keyword in CSS is the browser's own curve and is left.

## Components read only roles (no changeset: nothing an app sees changes)

The primitive scales (palette steps, `rounded-*`, `shadow-*`, `duration-*`) stay public in 16.0.0, as the tier 15.0.0 set up: they may change in a minor release, and apps should read the semantic roles instead. What changes is that components may not read them past a role, and the checks enforce it: colors through component tokens (`serupa/color-through-component-token`), corners through radius roles (`serupa/radius-through-role`), shadows through elevation roles (`serupa/shadow-through-role`, new), and durations and easings through motion roles (`tools/test/motion-tokens.mjs`; Loader's own loops are the listed exception). The seven places that read a shadow step now read the elevation role with the same shadow.

Renaming the primitives to private names, or removing them with their utility classes (`bg-zinc-700`, `shadow-md`), was considered and left out: 15.0.0 already lets them change in a minor, so a rename would make every app that reads one change its code for no new freedom.

## A component's inner classes are private (`.changeset/inner-classes-private-16.md`)

- **What breaks:** Nothing renames on the day. What changes is the promise: from 16.0.0 the classes of a component's inner parts (`.dk-btn__label`, `.dk-card__header`, any `dk-<block>__<part>`) may change in a minor or patch release, as they do whenever the markup inside a component is fixed or improved. Until now the Versioning rules counted every class as public, so a fix that moved an inner element had to wait for a major or break a promise.
- **Why:** The styling API is what can be kept: component tokens, `data-component`, `data-state` and the ARIA states, and the block and modifier classes (`.dk-btn`, `.dk-btn--primary`). The other systems we compared draw the same line, styling through tokens, data attributes and documented class names while their internal markup stays theirs. Holding every inner class stable holds back fixes to structure, accessibility and size, and a selector on an inner part usually means a token is missing, which is better fixed in the system once.
- **Migration:** `npx serupa-migrate --from 15` lists each line of your CSS or code that selects an inner part's class (it changes nothing). For each, use the component's token for that part (the token table in its README, or the debug overlay on the page), a `[data-component]` or `[data-state]` selector, or the block and modifier classes. Where none fits, open an issue asking for a token, and keep the selector until it ships. (`serupa-migrate` lists them / by hand)
