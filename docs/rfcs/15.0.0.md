# RFC: 15.0.0

**Status:** Being cut (14 November 2026). Diki moved 15.0.0 forward and waived the four-week deprecation window for it.

The first scheduled major (CONTRIBUTING.md, Release cadence and support). It removes the names 14.x deprecated, so one prop means one thing everywhere (the API naming table), and it settles what the package promises about its token tiers and where it lives. Every breaking changeset until its release adds a section here.

## Supported browsers: Chrome and Edge 129, Safari 26.4, Firefox 147

15.0.0 supports Chrome and Edge 129, Safari 26.4 and Firefox 147 (14.x: Chrome and Edge 123, Safari 17.5, Firefox 128). The two features that set it come next in this major: CSS anchor positioning places menus, popovers, tooltips and picker lists in place of the script that measures them now (Chrome 129, Firefox 147), and `@scope` keeps each component's styles to its own markup (Safari 26.4). Everything the old floor lacked is now plain CSS: entry and exit animations, view transitions, `content-visibility`, scrollbar styling and `scrollbar-gutter`, `round()` and `*-safe` alignment. Calendar's whole-pixel day size and ScrollArea's thin scrollbar no longer ask `@supports` first.

**Changeset** (`.changeset/browsers-15.md`, major): Supported browsers are now Chrome and Edge 129, Safari 26.4 and Firefox 147 (were Chrome and Edge 123, Safari 17.5 and Firefox 128). They have CSS anchor positioning and `@scope`, which the components now use. Nothing changes in your code: an app that must keep older browsers stays on 14.x, and a project with a `browserslist` raises it to match.

**Migration.** Nothing to change in code. An app that must keep older browsers stays on 14.x, which gets bug and security fixes for four weeks after 15.0.0. A project with a `browserslist` should raise it to at least `chrome >= 129, edge >= 129, firefox >= 147, safari >= 26.4, ios >= 26.4`.

## Prose styles stop at the components inside it

15.0.0 puts Prose's rules in `@scope (.dk-prose) to (…)`, which ends at any element with a `dk-` class. Before, Prose's list indents and markers, table, code and heading styles reached the components placed in it: a Pagination inside Prose got a 24px indent, list markers and taller buttons, a Kbd turned monospace, a Table's scroll box turned into a block. Now a component looks the same inside Prose as outside, and is still spaced from the block before it.

**Changeset** (`.changeset/prose-scope-15.md`, major): Prose styles only its own content: its list, table, code, heading and image rules stop at any element with a `dk-` class, so a component inside Prose looks as it does elsewhere. A page that relied on Prose restyling a component inside it styles that component with its own tokens instead.

**Migration.** Most apps change nothing. If you put your own `dk-`-prefixed classes on Markdown elements and wanted Prose to style them, rename those classes.

## Menus, popovers and tooltips follow their anchor in CSS

15.0.0 writes every anchored layer's position (Menu, Popover, Tooltip, HoverCard, Tour, Combobox, MentionInput and the date, time and cascade pickers) against CSS anchor positioning: `position-anchor` names the anchor, and `left` and `top` are `anchor()` plus the slide the script chose. A scroll now moves the layer with its anchor in the compositor, in the same frame, instead of one frame behind once the scroll handler has placed it again. Everything the script decided stays the same: the side and the flip, the slide that keeps it 8px inside the screen, the height cap with a scrollbar, the max width beside the anchor, the origin it grows from, and the phone keyboard's smaller viewport. CSS anchor positioning can't do those at this floor (`position-try-order` is Firefox 148, and nothing reports which fallback was taken). Each `anchor()` carries the pixel value as its fallback, so a layer whose anchor CSS can't reach sits where it did before.

**Changeset** (`.changeset/anchor-positioning-15.md`, patch): Menus, popovers, tooltips and pickers follow their anchor in CSS as the page scrolls (anchor positioning), so they no longer trail it by a frame. Where they open, and when they flip or shrink, is unchanged.

**Migration.** None. An app that sets its own `anchor-name` on a trigger keeps it: the layer's name is added to the list and taken off again on close.

## The names 14.x deprecated are gone

15.0.0 removes every prop, value, token and utility that 14.x deprecated: Tooltip `delay`, Switch `pending`, Field `layout`, Splitter `direction`, Fab and Toaster `position`, Drawer and NotificationCenter `side`, OfflineBanner `onChange`, Table, DataGrid and List `busy`, Button and Badge `loadingText`, `variant="default"` on Checkbox, CheckboxGroup, Radio and RadioGroup, Button's `icon`, the 20 component tokens that put the state first, and `animate-bounce`. Each had its new name beside it in 14.x. With Button's `icon` gone, an icon-only button is an IconButton, whose `label` the types require, so the planned "icon-only Button without a name is a type error" is done by the same removal. Some of these were deprecated less than four weeks before; Diki waived the window for this release (`tools/release-policy.json`).

**Changeset** (`.changeset/remove-deprecated-15.md`, major): lists each removed name and its replacement.

**Migration.** `npx serupa-migrate src --from 14 --write` makes the renames (it runs on 14.x too, since the new names already work there), then lists what it can't: each Button with `icon`, to make an IconButton with a label.

## Planned

These are agreed and wait for their pull requests. Each becomes a section with its changeset when it lands.

- **Primitive tokens are a tier of their own.** The README's Versioning table will say that palette and effect primitives outside the semantic layer (208 of the 635 typed tokens, which no component or theme reads) may change in a minor release, and they will stay out of the Figma and native exports. They aren't deleted. The semantic and component tokens keep the full major-only promise.
- **A private registry, under a scoped name.** 15.x is published as `@diki-stwn/serupa-ds` on GitHub Packages, never on the public npm registry (decided 13 November 2026). The package's name changes, so every import changes once; `serupa-migrate` rewrites `serupa-ds` in imports, CSS imports and CDN paths to the new name once it ships under it (`.changeset/migrate-15-tokens.md`; run from 14.x, it leaves them). If GitHub won't publish that scope from this repository, the name is `@dsgn-space/serupa-ds` instead. An app needs a token with `read:packages` and two `.npmrc` lines, which the install docs will give.

Done: `ROADMAP.md` dropped its stale "rename", "Later: page patterns" and "nothing deprecated" lines, and the README's Versioning section names the primitive tier from 15.0.0.
