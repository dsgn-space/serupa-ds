# RFC: 15.0.0

**Status:** Scheduled. Open for comments.

The first scheduled major (CONTRIBUTING.md, Release cadence and support). It removes names that were deprecated at least four weeks earlier, so one prop means one thing everywhere (the API naming table), and it settles what the package promises about its token tiers and where it lives. Every breaking changeset until its release adds a section here.

## Supported browsers: Chrome and Edge 129, Safari 26.4, Firefox 147

15.0.0 supports Chrome and Edge 129, Safari 26.4 and Firefox 147 (14.x: Chrome and Edge 123, Safari 17.5, Firefox 128). The two features that set it come next in this major: CSS anchor positioning places menus, popovers, tooltips and picker lists in place of the script that measures them now (Chrome 129, Firefox 147), and `@scope` keeps each component's styles to its own markup (Safari 26.4). Everything the old floor lacked is now plain CSS: entry and exit animations, view transitions, `content-visibility`, scrollbar styling and `scrollbar-gutter`, `round()` and `*-safe` alignment. Calendar's whole-pixel day size and ScrollArea's thin scrollbar no longer ask `@supports` first.

**Changeset** (`"serupa-ds": major`, added to `.changeset/` when 15.0.0 is cut, since a pending major makes the next daily release 15.0.0): Supported browsers are now Chrome and Edge 129, Safari 26.4 and Firefox 147 (were Chrome and Edge 123, Safari 17.5 and Firefox 128). They have CSS anchor positioning and `@scope`, which the components now use. Nothing changes in your code: an app that must keep older browsers stays on 14.x, and a project with a `browserslist` raises it to match.

**Migration.** Nothing to change in code. An app that must keep older browsers stays on 14.x, which gets bug and security fixes for four weeks after 15.0.0. A project with a `browserslist` should raise it to at least `chrome >= 129, edge >= 129, firefox >= 147, safari >= 26.4, ios >= 26.4`.

## Menus, popovers and tooltips follow their anchor in CSS

15.0.0 writes every anchored layer's position (Menu, Popover, Tooltip, HoverCard, Tour, Combobox, MentionInput and the date, time and cascade pickers) against CSS anchor positioning: `position-anchor` names the anchor, and `left` and `top` are `anchor()` plus the slide the script chose. A scroll now moves the layer with its anchor in the compositor, in the same frame, instead of one frame behind once the scroll handler has placed it again. Everything the script decided stays the same: the side and the flip, the slide that keeps it 8px inside the screen, the height cap with a scrollbar, the max width beside the anchor, the origin it grows from, and the phone keyboard's smaller viewport. CSS anchor positioning can't do those at this floor (`position-try-order` is Firefox 148, and nothing reports which fallback was taken). Each `anchor()` carries the pixel value as its fallback, so a layer whose anchor CSS can't reach sits where it did before.

**Changeset** (`"serupa-ds": patch`, added when 15.0.0 is cut): Menus, popovers, tooltips and pickers follow their anchor in CSS as the page scrolls (anchor positioning), so they no longer trail it by a frame. Where they open, and when they flip or shrink, is unchanged.

**Migration.** None. An app that sets its own `anchor-name` on a trigger keeps it: the layer's name is added to the list and taken off again on close.

## Planned

These are agreed and wait for their pull requests. Each becomes a section with its changeset when it lands.

- **One name for one idea (GR268).** A 14.x minor adds the naming table's names beside the old ones and deprecates the old ones (`.changeset/naming-aliases.md`): Tooltip `openDelay` (was `delay`), Switch `loading` (was `pending`), Field and Splitter `orientation` (were `layout` and `direction`), Fab and Toaster `placement` (were `position`), and Drawer and NotificationCenter `placement` (was `side`), and Checkbox, CheckboxGroup, Radio and RadioGroup `variant="plain"` (was `"default"`), and Table, DataGrid and List `loading` (was `busy`), and Button and Badge `loadingLabel` (was `loadingText`, which is only said, not shown). 15.0.0 then only removes the old names, at least 28 days after that release (`deprecations.mjs` enforces it). Still to come the same way: Select `onValueChange` beside its native `onChange`, Timeline `tone` beside `status`, and Text's `tone="default"` becoming its real default.
- **Component token names put the state last.** A 14.x minor renames the component tokens that put the state before the property (CONTRIBUTING.md, Token names), and the old names keep working as fallbacks: 20 tokens in Button, AvatarGroup, Calendar, Carousel, DataGrid, Pagination, PeriodPicker and Stepper (`--button-bg-disabled` was `--button-disabled-bg`, and so on; `.changeset/token-names-state-last.md` lists them). 15.0.0 removes the old names.
- **An icon-only Button without a name is a type error.** `href` with `type="submit"` already is. 15.0.0 also makes an icon-only Button without an accessible name (`aria-label`, `aria-labelledby` or `title`) a type error. It is the `button-icon-label` development warning today, so the migration note is: fix what that warning names before upgrading; an app that never sees it is unaffected. A controlled `value` without `onValueChange` or `readOnly` becomes a type error only after a 14.x minor has warned about it for four weeks; until that warning ships, it stays out of 15.0.0.
- **Primitive tokens are a tier of their own.** The README's Versioning table will say that palette and effect primitives outside the semantic layer (208 of the 635 typed tokens, which no component or theme reads) may change in a minor release, and they will stay out of the Figma and native exports. They aren't deleted. The semantic and component tokens keep the full major-only promise.
- **A private registry, under a scoped name.** 15.x is published as `@diki-stwn/serupa-ds` on GitHub Packages, never on the public npm registry (decided 13 November 2026). The package's name changes, so every import changes once; `serupa-migrate` gets a 15.0.0 transform that rewrites `from 'serupa-ds'` and `from 'serupa-ds/…'`. If GitHub won't publish that scope from this repository, the name is `@dsgn-space/serupa-ds` instead. An app needs a token with `read:packages` and two `.npmrc` lines, which the install docs will give.

Done: `ROADMAP.md` dropped its stale "rename", "Later: page patterns" and "nothing deprecated" lines, and the README's Versioning section names the primitive tier from 15.0.0.
