# Drag and drop

Dragging is quick for people who can do it, and impossible for some. Every drag in Serupa has a second way that needs no drag, and each step is shown and said. Use the component that fits; when you build your own, keep to the same rules.

## Pick the component

| People want to | Use |
| --- | --- |
| Put a list in their own order | [SortableList](?path=/docs/components-content-sortablelist--docs) |
| Move cards between columns | [Kanban](?path=/docs/components-content-kanban--docs) |
| Pick a set out of many | [TransferList](?path=/docs/components-forms-transferlist--docs) |
| Bring in files from their computer | [FileUpload](?path=/docs/components-forms-fileupload--docs) |
| Give one pane more room | [Splitter](?path=/docs/components-layout-and-type-splitter--docs) |
| Set a value along a track | [Slider](?path=/docs/components-forms-slider--docs) |

## The rules they all keep

- **A way without dragging, always** (WCAG 2.5.7). A handle that works with Space and the arrow keys, a "Move to…" menu, a button that opens the file picker, a field for the exact value. Dragging is the shortcut, never the only way.
- **A handle starts the drag**, not the whole row, so buttons and links in the row still work, text can still be selected, and a touch can still scroll the page.
- **Show where it will land before it lands.** The others make room, or a line marks the place, and a target that can take the drop is outlined. A place that can't take it shows nothing, so people don't let go there.
- **Say each step.** Picked up, moved to position 3 of 7, dropped, cancelled: each goes to screen readers as it happens (4.1.3).
- **Escape puts it back.** Nothing changes until the drop, and a cancelled drag leaves everything where it was.
- **Scroll at the edges**, so a long drag doesn't need a second hand.

## In your app

- **Let people undo a drop.** A row dropped one place off, or a card in the wrong column, is the most common slip. Store the move, then offer Undo in a [Toast](?path=/docs/components-feedback-toast--docs) (`toast.undo`), rather than asking "Move this card?" first.
- **Show progress when a drop starts work.** FileUpload shows each dropped file's upload from `fileStatus`, and removing the file cancels it. A drop that starts an import or a move on the server needs the same: a row or a placeholder where the content will be, with its state.
- **Say why a drop was refused**, in words, next to where it was dropped: the wrong file type, a full column, a card that can't leave its stage. FileUpload does this for files.
- **Moving many at once** takes selection first, then one action for the set ("Move 4 to…"), which also serves people who don't drag. If the set can be dragged, show how many are moving.
- **Don't make drag the only sign.** A page that can take dropped files says so in words and has the button too. Nobody finds a drop area by trying.
- **A very long list** needs "Move to top", "Move to bottom" or a position field beside the handle: a drag across 200 rows is slow, with the keyboard most of all.

## Do and don't

| Do | Don't |
| --- | --- |
| A handle, plus "Move to…" in each card's menu | Cards that move only by dragging |
| Undo in a toast after a move | "Are you sure you want to move this?" |
| Outline the column a card will land in | Show nothing until the drop, then a surprise |
| "PDF only. report.docx wasn't added." by the drop area | A file that silently isn't added |
