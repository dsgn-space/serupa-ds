# Testing your app

`@diki-stwn/serupa-ds/testing` drives Serupa's components in your own tests the way people use them, so a test of your checkout or your settings page doesn't have to know how a combobox's keyboard works or where its options are drawn. Serupa tests every component itself; these helpers are for testing what you build with them.

## Testers for the widgets that take more than a click

A tester takes the widget's element and a `user`, and gives you what a person would do with it. Each finds the widget's parts by role, state and name, never by a `dk-` class, and waits for the widget to open, close or change before it returns, so a test written with one keeps passing when Serupa's markup changes.

```tsx
// not compiled: it needs your test runner, Testing Library and your app's own Checkout
import { render, screen } from '@testing-library/react';
import { userEvent } from '@testing-library/user-event';
import { combobox, datePicker, menu, table, tabs } from '@diki-stwn/serupa-ds/testing';

test('ships an order to Canada next week', async () => {
  const user = userEvent.setup();
  render(<Checkout />);
  await combobox(screen.getByRole('combobox', { name: 'Country' }), { user }).choose('Canada');
  await datePicker(screen.getByLabelText('Delivery date'), { user }).pick('2026-12-24');
  await user.click(screen.getByRole('button', { name: 'Place order' }));
  expect(await screen.findByText('Order placed')).toBeVisible();
});
```

| Tester | Give it | What it does |
| --- | --- | --- |
| `combobox()` | The field (`role="combobox"`), or an element holding it | `open()`, `choose(option)` by pointer or `{ by: 'keyboard' }`, `type(text)`, `close()`; reads `value()`, `options()`, `selected()`, `active()`. An option a long list hasn't drawn yet is found by typing its text. |
| `menu()` | The button that opens the menu | `open()`, `choose(item)`, or a path into submenus: `choose(['Share', 'More apps', 'Chat'])`; `close()` (focus goes back to the button); reads `items()`. |
| `tabs()` | The tab list, or an element holding it | `select(tab)`; reads `tabs()`, `selected()` and the selected tab's `panel()`. |
| `table()` | The table, or an element holding it | `sort(column, 'ascending' \| 'descending')`, `selectRow(row)`, `selectAll()` (both take `false` to clear); reads `rows()`, `columns()`, `row()`, `cell(row, column)`, `sortDirection()`, `selectedRows()`. A row is found by the text of any of its cells. |
| `calendar()` | A Calendar or RangeCalendar, or an element holding it | `pick(date)` moves to its month from the keyboard and presses the day; reads `days()` and `selected()` as `YYYY-MM-DD`. |
| `datePicker()` | The DatePicker's field, or the element holding it | `open()`, `pick(date)` (a `Date` or `YYYY-MM-DD`), `close()`; reads `value()`, the text in the field. |

**Picking an option, item, tab, row or column.** Pass its name (`'Canada'`, exact), the text of one of its parts (an option's description), a `RegExp`, its index, or the element itself. When nothing matches, the error lists what's there.

**The `user`.** Anything with user-event's `click(element)` and `keyboard(text)`: `userEvent.setup()` from `@testing-library/user-event` in jsdom or happy-dom, or `userEvent` from `vitest/browser` in Vitest's browser mode (what Serupa's own tests use). `combobox().type()` also needs `type(element, text)`, which both have. Pass `timeout` (ms, default 1000) to wait longer for a slow test machine.

**What they don't do.** They act on one widget at a time and leave your app's own assertions to you. A native `Select` needs no tester: use `user.selectOptions()`. Dialogs, drawers and toasts are found with `getByRole('dialog')` and `getByRole('status')` like anything else.

## Screenshots in every theme

Serupa checks its components in all six themes. `forEachTheme()` gives your own screens the same check in Playwright: it draws the page in each theme in turn, with transitions off and the color scheme to match, and calls you back to take the picture.

```ts
import { test, expect } from '@playwright/test';
import { forEachTheme } from '@diki-stwn/serupa-ds/testing';

test('checkout', async ({ page }) => {
  await page.goto('/checkout');
  await forEachTheme(page, async (theme) => {
    await expect(page).toHaveScreenshot(`checkout-${theme}.png`);
  });
});
```

Pass `{ themes: ['blue-light', 'blue-dark'] }` for fewer themes. Afterwards the page is as it was, even when a screenshot fails.
